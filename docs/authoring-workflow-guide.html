Test Authoring Standard Operating Procedure

End-to-End Authoring Workflow: Component & POM to Spec

A step-by-step developer guide showing the exact coding workflow: how to model Web Page Objects & Components, construct REST API Services with Zod Schemas, build Database Repositories, inject them into Fixtures, and author complete Spec files.

1

Web UI: From Reusable Component → Page Object Model

src/pages/components/ → src/pages/

In our framework, we never write 1000-line monolithic page objects. Instead, every modal, table, or form is authored as an isolated BaseComponent, and the domain BasePage simply composes them.

Step 1.1: Author Component Primitive

src/pages/components/ModalComponent.ts
import { Locator } from '@playwright/test'; import { BaseComponent } from './BaseComponent'; export class AppointmentModal extends BaseComponent { constructor(root: Locator) { super(root); // strictly scoped to modal root } private get doctorInput() { return this.root.getByLabel('Doctor'); } private get submitBtn() { return this.root.getByRole('button', { name: 'Confirm' }); } async fillAndSubmit(doctorName: string): Promise<void> { await this.doctorInput.fill(doctorName); await this.submitBtn.click(); } }

Step 1.2: Compose Domain Page Object

src/pages/AppointmentPage.ts
import { Page } from '@playwright/test'; import { BasePage } from './BasePage'; import { AppointmentModal } from '@components'; export class AppointmentPage extends BasePage { readonly appointmentModal: AppointmentModal; constructor(page: Page) { super(page); // Bind component to page locator this.appointmentModal = new AppointmentModal( page.locator('[role="dialog"]') ); } async openModal(): Promise<void> { await this.page.getByRole('button', { name: 'Book' }).click(); } }
Rule of Idiomatic POM: Never write try/catch around Playwright clicks or inject manual sleeps like await page.waitForTimeout(1000). Let Playwright’s native auto-waiting and actionability checks do the waiting.
2

REST API: From Zod Contract Schema → Domain Service

src/schemas/ → src/services/

API services wrap HttpDriver to send typed requests and automatically validate responses against runtime Zod contract schemas to catch backend contract drift.

Step 2.1: Define Zod Contract Schema

src/schemas/appointment.schema.ts
import { z } from 'zod'; export const AppointmentResponseSchema = z.object({ id: z.string(), doctor: z.string(), status: z.enum(['pending', 'confirmed']), date: z.string(), }); export type AppointmentResponse = z.infer<typeof AppointmentResponseSchema>;

Step 2.2: Implement API Domain Service

src/services/AppointmentService.ts
import { BaseService } from './BaseService'; import { AppointmentResponseSchema, AppointmentResponse } from '@schemas'; export class AppointmentService extends BaseService { constructor(http: HttpDriver) { super(http, '/appointments'); } async create(payload: { doctor: string; date: string }): Promise<AppointmentResponse> { // Automatically passes through SchemaValidator return this.post<AppointmentResponse>( '', payload, undefined, AppointmentResponseSchema ); } }
3

Database: Typed Repository Pattern over DbClient

src/database/repositories/

Tests never execute raw string SQL queries. All database operations extend BaseRepository, ensuring connection pooling, SQL injection prevention, and parameterized execution.

Author Domain Repository

src/database/repositories/AppointmentRepository.ts
import { BaseRepository } from './BaseRepository'; export interface AppointmentRecord { id: string; doctor: string; status: string; created_at: Date; } export class AppointmentRepository extends BaseRepository { constructor() { super('appointments'); } async findById(id: string): Promise<AppointmentRecord | null> { return this.findOneBy<AppointmentRecord>('id', id); } async deleteById(id: string): Promise<number> { return this.deleteBy('id', id); } }
4

Fixtures: Wiring Dependencies into Playwright's Engine

src/fixtures/

Now wire the new Page Object, Service, and Repository into test fixtures using base.extend so test files receive them cleanly via parameters:

src/fixtures/ui.fixture.ts & src/fixtures/test.fixture.ts

// In ui.fixture.ts export const uiTest = base.extend<UiFixtures>({ appointmentPage: async ({ page }, use) => { await use(new AppointmentPage(page)); }, }); // In test.fixture.ts: merged hybrid fixture export const hybridTest = mergeTests(uiTest, apiTest, dbTest);
5

Writing the Test: From Imports to 360° Assertion

tests/hybrid/appointment.spec.ts

Here is how the authoring workflow comes together in the final specification file:

/** * Complete 360° E2E Spec: * 1. Pre-seed via API Service * 2. Complete flow via UI Component POM * 3. Validate database record via Repository * 4. Register for automatic LIFO teardown */ import { hybridTest as test, expect } from '@fixtures'; test.describe('Patient Appointment Lifecycle @smoke', () => { test('Complete appointment booking: API → UI → DB → Auto-Cleanup', async ({ basePage, // Base UI navigation http, // API client driver db, // Database client userRepo, // DB User repository registry, // LIFO cleanup manager logger, // Winston structured logger }) => { logger.info('Step 1: Check database connectivity health'); const isDbUp = await db.isHealthy(); expect(isDbUp).toBe(true); logger.info('Step 2: Seed prerequisite user via API'); // Perform API seed and register for post-test cleanup registry.register('patient', 'usr_temp_123', async () => { logger.info('Tearing down test patient record...'); await userRepo.deleteBy('email', 'patient.temp@aura-eyecare.com'); }); logger.info('Step 3: Execute UI journey through POM'); await basePage.navigate('/dashboard'); expect(basePage.getUrl()).toContain('dashboard'); logger.info('Step 4: Verify directly in PostgreSQL database'); const record = await userRepo.findByEmail('patient.temp@aura-eyecare.com'); // Even if this expect fails, registry.cleanupAll() is GUARANTEED to execute! expect(record).toBeDefined(); }); });
