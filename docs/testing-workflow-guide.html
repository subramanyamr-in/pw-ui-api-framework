The 360° Hybrid E2E Workflow Lifecycle

In mission-critical enterprise applications, verifying UI state alone is insufficient. The hybrid workflow ensures that an action taken in the UI propagates through the API layer, commits accurately to the database, and is automatically dismantled post-test.

1

Fast Setup & Data Seeding via REST API

Instead of slowly navigating through multiple UI pages to create prerequisite data, tests invoke domain API services (e.g. AuthService, HttpDriver) to seed records instantly via high-speed headless HTTP requests.

// Seed prerequisite test data in <100ms without browser overhead const authResponse = await authService.login({ email: 'admin@aura-eyecare.com', password: 'Password123!', }); // Token is automatically stored in process-safe TokenVault for all workers
2

Web UI User Journey Execution

The test triggers real user interaction through component-driven page objects. Playwright navigates, fills forms, submits dialogs, and validates visible feedback leveraging native auto-waiting.

// Navigate and submit form through component-driven POM await basePage.navigate('/appointments'); await appointmentModal.fillAndSubmit({ patientId: 'usr_abc123', doctor: 'Dr. Smith', date: '2026-10-15', }); await expect(notificationBanner.locator()).toContainText('Appointment Confirmed');
3

Direct Database State Verification (Repository Pattern)

A UI success message can mask asynchronous queue drops or data corruption. The test immediately queries PostgreSQL through DbClient and repositories to confirm persistence and integrity.

// Query DB directly to prove the database record exists with correct attributes const record = await userRepo.findByEmail('patient@aura-eyecare.com'); expect(record).not.toBeNull(); expect(record?.is_active).toBe(true);
4

Automated LIFO Teardown via TestDataRegistry

Any created entity is registered with TestDataRegistry. When the test finishes (even if an assertion fails midway!), registered cleanups execute in reverse order (LIFO), eliminating test data pollution.

// Register for post-test cleanup; executed unconditionally in fixture teardown! registry.register('appointment', appointmentId, async () => { await http.delete(`/api/appointments/${appointmentId}`); });

import { hybridTest as test, expect } from '@fixtures'; test.describe('Complete 360° Appointment Lifecycle @smoke', () => { test('Seed patient via API, book via UI, verify in PostgreSQL & auto-cleanup', async ({ basePage, // Web UI Layer http, // REST API Layer db, // Database Client userRepo, // Typed Repository registry, // Automated Cleanup Tracker logger, // Structured Winston Logger }) => { logger.info('Step 1: Checking PostgreSQL connection health...'); const isHealthy = await db.isHealthy(); expect(isHealthy).toBe(true); logger.info('Step 2: Navigating Web UI with pre-authenticated state...'); await basePage.navigate('/'); expect(basePage.getUrl()).toContain('aura-eyecare.vercel.app'); logger.info('Step 3: Registering dynamic test data for guaranteed cleanup...'); registry.register('patient', 'temp_usr_99', async () => { logger.info('Auto-cleaning test patient record...'); // e.g. await userRepo.deleteBy('id', 'temp_usr_99'); }); // Teardown is guaranteed even if future assertions fail! }); });
